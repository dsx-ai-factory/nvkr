# Direct public-source OS builds

Experimental source-producer catalog for NKE v0.21.0 OS inputs. It uses NKD's existing catalog, source preparation, graph compiler and local executor. It is not selected by the maintained OS/M2 Definitions and is not yet a replacement for their package graph.

## Implemented producers

Every producer supports native Linux AMD64 and ARM64. The catalog has 13 independently locked Git sources and 14 outputs:

| Source | Versions | Declared output |
|---|---|---|
| Kubernetes | 1.34.2, 1.35.3, 1.36.3 | Tar of kubeadm, kubectl, kubelet, kube-apiserver, kube-controller-manager, kube-scheduler and kube-proxy |
| containerd | 2.1.7, 2.2.3, 2.3.0 | Tar of containerd, ctr and containerd-shim-runc-v2 |
| cri-tools | 1.34.0, 1.35.0, 1.36.0 | crictl binary |
| CNI plugins | 1.6.0 | Tar of the 18 Linux plugins |
| Helm | 3.20.2, 4.1.4 | helm binary |
| SPIRE TPM plugin | 1.9.0 | Separate tpm_attestor_agent and get_tpm_pubhash binaries |

These commands compile upstream source directly. They do not invoke NKE's `os-image/packages`, acquire the corresponding release binaries, or silently fall back to them on a build failure. Tar files are binary bundles, not Debian packages or OCI images. A `host-package` output in this experimental catalog is a raw binary, not a `.deb`.

## Source and compiler closure

[registry.yaml](catalog/registry.yaml) owns exact source-version constraints, producer commands and per-architecture compiler image digests. [pins.lock.yaml](catalog/pins.lock.yaml) is generated by NKD and records the exact Git commit, tree and source epoch. Refresh it only through the owning command:

```sh
make build
bin/nkdctl catalog bump --dir definitions/nke-os-source/catalog --all --timeout 15m
```

The source preparation lane is network-capable. For TPM, Helm and crictl, it downloads Go modules under the upstream checksums, verifies them, vendors offline, and checks that `go.mod` and `go.sum` stayed unchanged. Kubernetes, containerd and CNI use the vendor tree committed at their pinned Git revision. Compilation is offline with a read-only authenticated source tree and a separate output directory.

The experimental compiler inputs are native Docker Official Image Go 1.27.1 Bookworm manifests, measured and selected by digest. This does not assert organizational license/security review, upstream signature verification, qualified execution, or compatibility with every future package consumer. These reviews and full consumer tests are required before production selection. Rebuilt bytes receive new identities; upstream download hashes in the release SBOM are not expected hashes for rebuilt outputs.

Helm's pinned Git trees contain external symlinks used only by negative-test fixtures. Diagnostic Local preparation checks their exact targets and removes those named fixture entries using Git before closure authentication. This transformation is included in the vendor-command identity; the receipt binds the resulting bytes. The production held `ExecNode` vendor route authenticates the pristine source before preparation and still rejects these links. Its admitted preparation boundary must be resolved before selecting Helm in that production route; this catalog does not weaken that rejection.

## Tests

The ordinary repository gate resolves all 14 producers for both architectures and checks isolated offline build nodes, no acquired producer substitution, and coded rejection of a missing compiler pin.

The opt-in integration test uses real source preparation and containers. On a native Linux host with Docker:

```sh
NKD_OS_SOURCE_RUNTIME=docker go test -v ./pkg/nkd/buildgraph \
  -run '^TestNKEOSPublicSourcesLive$' -count=1 -timeout 75m
```

For native Linux Podman, use `NKD_OS_SOURCE_RUNTIME=podman`. SELinux enforcing hosts need the disposable test workspace and `TMPDIR` prepared with a shared container label; see the [recorded Podman setup](../../docs/evidence/2026-10-07-direct-os-source-builds.md). No host SELinux policy is disabled.

An optional comma-separated `NKD_OS_SOURCE_COMPONENTS` selects exact producer names for a smaller diagnostic. Without it, all 14 producers run. The test recomputes output size and SHA-256, checks raw binary ELF architecture, checks exact tar membership, and executes Helm/crictl version probes. It does not exercise TPM hardware or start Kubernetes/containerd services. Its result is explicitly unqualified.

The read-only [source-build workflow](../../.github/workflows/nke-os-source-build.yaml) runs the integration test on native `ubuntu-24.04` and `ubuntu-24.04-arm` hosted runners. It needs no private NKE source or publication credentials. This hand-authored diagnostic workflow is not the generated Run/Release pipeline.

## Required remaining migration

The requested complete removal of NKE package-folder use is not implemented by this catalog alone:

1. Add and exercise SPIRE, runc with its required seccomp closure, CoreDNS, etcd, pause, Calico/Tigera and all embedded image producers. Existing OVN and agent source builds also need their packaging boundary checked.
2. Package authenticated binaries and rebuilt OCI images using pinned packaging tools, preserving package names, paths, dependencies, hooks, units and runtime image references. Eliminate the indirect NKE-agent packaging dependency on the package folder.
3. Declare the unavailable-public-source DSX IMDS exception in the executable package catalog and artifact lock, warn during preparation, and acquire the retained bytes successfully. Do not omit it or substitute an older plugin-free SPIRE package.
4. Connect the producers to image-inputs and the maintained OS/M2 Definition, regenerate matching overlays and Plans through their owning commands, and execute fresh AMD64 and ARM64 image builds plus package/boot/runtime selection tests.

The [release inventory](../../docs/nke-v0.21.0-os-dependency-inventory.md) contains the exact released inputs and remaining source mappings. Ubuntu packages remain the separately captured APT lane; this change does not rebuild Ubuntu itself or claim byte-reproducible QCOW2 images.

### Unavailable-public-source exception

DSX IMDS has no established public Git URL/approved source revision in the release inventory. The user's policy is to retain its existing per-architecture digest-pinned payloads and flag the exception, not to stop building public components. The release-declared URLs returned anonymous HTTP 403 on October 7. An accessible existing mirror or held payload with the same digests is still required for a complete package/image build.

This experimental public-source-only catalog does not claim complete release membership and does not acquire DSX. The live test prints the unresolved prebuilt exception explicitly. It never reclassifies a publicly available component as unavailable merely because its source build fails.
