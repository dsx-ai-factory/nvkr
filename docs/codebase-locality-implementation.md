attempt (`lifecycle.PrepareFiles`) → execution/generation (`factory`) → checked publication (`delivery`) →
policy-scoped Release verification (`lifecycle`). Specialized identity, trust, signing and source-execution
modules retain their distinct invariants. No generic shared-types or orchestration framework was introduced.

## Identity and compatibility

Definition and Environment authoring schemas remain unchanged. Run Plan and artifact graph use v4 because
copied compiler handoffs and executable producer projections are removed. Production buildType URLs use v2;
production predicates bind the original Definition and Environment digests rather than discarded handoff
identities. Retired digest families remain reserved and cannot mint new identities. Public Run/Release and
publication schemas retain their existing versions. The release-content canonical shape is preserved by a
fixed digest contract; only its implementation owner changes.

Generated payload retirement still requires the previous ownership manifest and unchanged bytes/modes.
The migration retires redundant producer graph files through that writer, not by deleting or editing generated
files directly. Process and trust transitions retain complete validation and exact-byte checks.

observed outputs also remain separate: reducing duplication must not collapse the completeness comparison.

## Validation

Full uncached native unit tests and `make check` passed, including formatting, vet, golangci-lint, ShellCheck
and uncached race/coverage tests (71.0% statements). Affected Linux race checks, NKE/AICR generated-bundle
checks, Actionlint and `git diff --check` passed. The fixture migration supplied complete producer records from
the exact Plan and payload bytes; production result validation was retained.

A [fresh local NKE run](evidence/2026-09-18-code-locality-local-build.md) built all three outputs in 272 seconds,
published to the loopback registry, pulled the closure and ran the recovered CLI. Final-source observation
matched the recorded producer bytes, outputs and content identity; held publication checks matched both roots.
Signing was dry-run only. No new hosted, authenticated-consumer or qualified acceptance is claimed.
The local scheduler uses bounded ready batches; no throughput improvement has been measured.

## Incidental baseline repair

The baseline NKE catalog declared `linux/amd64f` for nkectl. This invalid target prevented catalog admission
and all maintained compilation. It is corrected to `linux/amd64`; producer commands, source pins and the
NKE checkout are unchanged. This is a baseline input repair, separate from the ownership refactor.
