# Development guide

Use the Go version in [.go-version](.go-version) with `GOTOOLCHAIN=local`, the golangci-lint version pinned in
[Merge Gate](.github/workflows/merge-gate.yaml) built with a compatible Go compiler, and ShellCheck. Docker or
podman is needed for actual local builds; planning and generation need neither a registry nor a source checkout.
Linux is required for held-executable qualified/signing authority; macOS supports development, planning and
contract tests. Match CI's linter version when diagnosing a gate failure.

The ordinary test gate (`go test ./...`, `make test`, and `make check`) also requires Bash 3.2 or later,
Git, `jq`, GNU coreutils `timeout` or `gtimeout`, and a SHA-256 utility (`sha256sum` or `shasum`) on `PATH`.
The required [authoring lab regression](docs/examples/authoring-lab/README.md) uses these tools and fails
if a prerequisite is missing. `make check` additionally requires Python 3 (`python3` on `PATH`) for
`make test-ci-tools`, which tests the CI timing report parser using only the Python standard library.
On macOS with Homebrew, install the additional JSON, timeout, and Python tools with:

```sh
brew install jq coreutils python
```

The lab discovers `gtimeout` directly on macOS; no `timeout` alias or unprefixed coreutils setup is needed.

```sh
make build
make check
```

`make help` lists targets. The repository completion gate is `make check`. To run its checks individually,
with uncached tests and an additional whitespace check, use:

```sh
make fmt-check
make license-header-check
go test ./... -count=1
go vet ./...
golangci-lint run
make shellcheck
make test-ci-tools
make vulncheck
git diff --check
```

The operator-facing site published with Fern is a separate gate. Pages are those listed in
[docs/index.yml](docs/index.yml); other documents stay on GitHub. After changing a published page, its navigation
or `fern/`, run `make docs-check`, which needs Node and the Fern CLI (`npm install -g fern-api@latest`; Fern is not
pinned). CI runs the same target as the `docs` job of the merge gate. The Fern checks run on an isolated copy of
only the listed pages, so a published page must not link to an unpublished page or to a file outside `docs/`; use a
GitHub URL for those. Registered release versions are ignored by this check (it needs `yq` once any exist).

For concurrency or process-lifetime changes, run targeted race tests on the affected packages. Whole-suite
race detection and coverage are opt-in with `make test-race`; `make test-full` additionally enables expensive
capacity and integration fixtures. Changes to sign/pipeline authority also need Linux tests. Containerized tests
require an init process to reap children; Linux signing fixtures build static helpers while retaining race
instrumentation in the parent suite.
Passing these checks proves contracts, not CI, signing-service or registry acceptance.

## Work with product inputs

The [lifecycle guide](docs/lifecycle.md) covers Definition → Run → Release. Begin with `definition validate`,
`run plan`, or `run local --dry-run`. Actual Runs require a new attempt identifier; stored descriptions are not
resume capabilities. The [demo index](demos/README.md) provides bounded generation, identity and local-build
journeys with their prerequisites.

The committed bundle selects the 34-output [M2 candidate](definitions/nke-m2/README.md).
Regenerate it after changing its Definition, Environment, catalog pins or generator code:

```sh
go run ./cmd/nkdctl run generate \
  --definition definitions/nke-m2/definition.yaml \
  --environment definitions/nke-m2/environment-github.yaml --engine github --root .
go run ./cmd/nkdctl run generate \
  --definition definitions/nke-m2/definition.yaml \
  --environment definitions/nke-m2/environment-github.yaml --engine github --root . --check
```

Use the same generator version and input selection for generation and checking. Generated files are owned by
the generator; edit authored inputs. Selected producer pin changes are build-identity changes; destinations and runtime/signing
configuration belong to Environment. The complete generated Plan is the executable document; there are no separately authored compiler handoffs.

`make workflows-check` builds the generator with the committed `dev`/`unknown` stamp and checks this same
bundle. A `make build` CLI has a Git-derived version and can legitimately report different generated bytes.
Use [scratch generation](docs/generate-pipeline.md) for v1, deploy, or other examples; generating them with
`--root .` would replace the M2 workflow.

## Generated and handwritten GitHub files

The generator owns `.github/workflows/nkd-run.yml` and every manifest member beneath `.github/nkd-run/`.
Its checker rejects unexpected managed-directory entries, including symlinks. Human-maintained repository
workflows, Dependabot configuration, and issue templates have separate ownership. Action pins for generated
CI come from its selected catalog and lock, rather than edits to rendered YAML.

Pull requests check generation. The maintained publication route admits default-branch manual dispatch;
only its isolated artifact-signing and SBOM-attestation jobs receive OIDC minting permission. Generic hosted
runners are the default, with ADR-18's explicitly admitted native ARC disk routes. Dated validation-branch
exceptions and completed Runs are scoped in [reconciliation](docs/adr/reconciliation.md).

## Test timing and cache use

Use `make test GO_TEST_FLAGS="-json -count=1"` to capture uncached ordinary test events. CI retains the
event stream for seven days and summarizes slow packages/tests, including failures. Its check
cache is scoped by platform, exact Go version, dependencies, and commit; a compatible prior check cache is
restored and an updated cache saved only after successful checks. Other jobs cannot populate that key.

Use the summary to select a slow test before profiling it. CI may report unchanged packages as cached;
use the uncached local run above for complete timings. Package durations overlap and cannot be summed as
workflow wall time. Race detection and coverage change execution costs; keep instrumentation consistent when
comparing measurements. These uninstrumented commands match the ordinary test gate and inspect canonical
string encoding and the full-size disk-publication inventory fixture:

```sh
go test -run '^TestMarshalStringBytes$' -bench BenchmarkMarshalString -benchtime=3x -count=3 ./pkg/nkd/canonical
profile_dir=$(mktemp -d)
NKD_TEST_EXTENDED=1 go test \
  -run '^TestDiskPublicationLargeInventoryAttestationReadback$' -count=1 \
  -o "$profile_dir/delivery.test" -cpuprofile "$profile_dir/delivery.cpu" ./pkg/nkd/delivery
go tool pprof "$profile_dir/delivery.cpu"
```

The delivery command explicitly enables the expensive fixture; it is not part of the ordinary test gate.
These measurements diagnose local test costs, not hosted build duration or Release acceptance.

## Opt-in integration checks

The ordinary suite skips integrations requiring external tools, private source, or exceptional host capacity.
A skipped test provides no interoperability evidence. With an installed Helm executable, run the
[mapping fixture](pkg/nkd/factory/helm_mapping_test.go):

```sh
NKD_TEST_HELM_BINDINGS=1 go test ./pkg/nkd/factory \
  -run '^TestMappedBindingsWithHelm$' -count=1 -v
```

For the source-chart case, set `NKD_NKE_CHART` to the controller chart from the exact upstream revision
you intend to exercise, and run `TestNKEDeclarativeBindingWithHelm`. Both tests render local chart bytes;
they do not build images, publish, install or verify upstream signatures.

The Linux [public disk-issuer fixture](pkg/nkd/factory/disk_evidence_runtime_linux_test.go) uses a controlled
native ELF daemon protocol and synthetic capture/disk bytes. On a native host with sufficient observed
composition capacity, explicitly request its issuer and memory-profile checks:

```sh
NKD_TEST_DISK_EVIDENCE_RUNTIME=1 go test -race ./pkg/nkd/factory \
  -run '^TestDiskEvidencePublicRuntime(Issuer|RejectsMemoryProfile)$' -count=1 -v
```

An opted-in run fails on inadequate capacity rather than skipping its positive case. It checks public
owner/receipt/export boundaries, without executing Docker, Packer, guestfish, Syft or a real NKE image.
Actual native disk build/inspection observations remain separately scoped in
[reconciliation](docs/adr/reconciliation.md#native-disk-execution-and-inspection).

## Repository layout

- `definitions/`: tutorial, deploy, combined candidate, and OS-image Definitions, Environments, and catalogs.
- `testdata/examples/`: multi-output, worker, and catalog contract fixtures.
- `pkg/nkd/definition/`: authored inputs, admission and identity.
- `pkg/nkd/factory/`: complete compilation, Run operations and provider generation.
- `pkg/nkd/lifecycle/`: immutable attempts and policy-scoped Release consumption.
- `pkg/nkd/delivery/`: checked publication content and bounded held-resource lifetime.
- `.github/nkd-run/`: generated NKE bundle; regenerate from its Definition and Environment.
- `toolchains/`: development adapter toolchains and helper pins; maintained demos use their declared utility image.

Package comments and the ownership map below identify starting operations. CLI and SDK files group operations
by family; factory execution uses `execute_` files, and `outputs_observed.go` owns the independent output join.
Catalog resolution, pin maintenance, and producer admission have distinct files within their owning package.

## Find the owner

| Work | Owner |
|---|---|
| Definition/Environment admission and identity | `pkg/nkd/definition` |
| Immutable attempts and Release consumer workflow | `pkg/nkd/lifecycle` |
| Complete compilation, output joins, scheduling, packaging and provider generation | `pkg/nkd/factory` |
| Catalog/pins, resolution and canonical identity | `catalog`, `buildgraph`, `target`, `ir`, `canonical` |
| Producer execution, observations and qualified receipts | `pipeline`, `profile` |
| Bounded archive transport and descriptor-safe paths | `internal/transportarchive`, `internal/securepath` |
| Subject-bound evidence and verification | `attest`, `sbom`, `provenance`, `trust`, `sign` |
| Release authority and delivery | `release`, `status`, `delivery` |
| Public adapters | `client/v1`, `cmd/nkdctl` — delegate authority |

Read the relevant current ADR and [reconciliation row](docs/adr/reconciliation.md) before changing authority.
Use package-issued opaque receipts, admit capabilities before side effects, validate the complete graph at
executable boundaries, and preserve exact subject/policy identities. Low-level diagnostic APIs cannot turn
caller-authored descriptions into authority.
